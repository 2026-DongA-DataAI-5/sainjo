# 관리 판단 서비스

정비 기준 출처 대조와 이용 권리 상태는 [`SOURCE_RIGHTS_REVIEW.md`](SOURCE_RIGHTS_REVIEW.md)를 따릅니다. 현재 K5 후보 규칙은 프로토타입 계산에 사용하지만, 모든 결과에 **사용 권리 확인 중**을 표시합니다. 이 표시는 권리 허락이나 기아의 서비스 승인으로 볼 수 없습니다.

`management.py`는 차량, 입력된 관리 기록, 적용 기준, 서버가 주입한 기준일을 받아 관리 항목별 안내 1건을 반환합니다. API는 차량에 해당하는 규칙별 결과를 모아 반환합니다. 순수 Python 모듈이며 Flask, DB, HTML, 네트워크, 현재 시각에 의존하지 않습니다.

```python
from chageun.services.management import evaluate_management

item = evaluate_management(vehicle, records, rule, as_of_date="2026-06-01")
```

## 입력과 출력

- `vehicle`: 공통 기준의 차량 필드. `mileage=0`은 측정된 0km이고 `None`은 미확인입니다.
- `records`: `vehicle_id`, 항목별 `item_key`, 선택 위치 `component_position`, `kind`, `work_type`, `date`, `mileage`를 가진 사용자 입력 기록입니다. 현재 입력 가능한 항목은 엔진오일, 점화플러그, 구동벨트, 브레이크액, 공조장치용 에어필터, 브레이크 패드·디스크, 볼 조인트, 로워암입니다. 로워암과 볼 조인트는 별도 항목이며, 로워암은 기록 전용이라 교환 주기 계산에 쓰지 않습니다. 위치를 모르면 `unknown`으로 저장합니다.
- `rule`: 기준 사양, 운행조건, 거리·개월 주기, 출처, 확인일, 권한·검토 상태를 포함합니다. 승인된 기준은 `rights_status="allowed"`, `review_status="reviewed"`, `is_fixture=False`일 때 계산합니다. 현재 K5 후보는 `rights_status="pending_confirmation"`, `review_status="source_checked_pending_approval"`인 경우 프로토타입 계산에 사용하고 결과마다 `rights_review_pending=True`, `rights_status_label="사용 권리 확인 중"`을 반환합니다. 다른 미승인 상태는 계산을 보류합니다. 시험 fixture는 `rights_status="test_fixture"`, `review_status="reviewed"`, `is_fixture=True`여야 합니다.
- `as_of_date`: `YYYY-MM-DD` 형식의 평가 기준일. 서버 또는 호출자가 주입합니다.
- 반환 dict는 공통 v1.1 필드(`item_key`, `history_status`, `timing_status`, `labels`, `next_mileage`, `next_date`, `reasons`, `missing_fields`, `rule_id`, `source`, `source_url`, `checked_date`, `questions`, `is_fixture`, `action`, `condition_based`, `component_position`, `interval_km`, `interval_months`, `first_interval_km`, `first_interval_months`)를 가집니다. 출처 URL은 기아 공식 취급설명서 도메인만 링크로 제공합니다.

`timing_status`는 `due`, `upcoming`, `partial`, `unknown`, `unsupported` 중 하나입니다. 도달 여부는 거리·기간 축별로 계산합니다. 계산 가능한 축이 하나라도 도달하면 `due`, 필요한 모든 축이 확인되어 미도달이면 `upcoming`, 일부 축만 계산되면 `partial`입니다. 계산 근거가 없으면 `unknown`, 사양이나 항목이 적용 범위 밖이면 `unsupported`입니다.

## 안전한 계산 원칙

- 후보 규칙은 K5 DL3 2021년형 2.0 가솔린 G2.0 CVVL 자동변속기만 정확히 일치시킵니다. 다른 연식이나 사양으로 확대하지 않습니다.
- 운행조건은 기준과 차량 양쪽이 확인되고 일치해야 합니다. `unknown` 조건으로 주기를 확정하지 않습니다.
- 자료 없음은 미정비를 뜻하지 않습니다. 기록이 없거나 작업유형이 `unknown`뿐이면 이력 상태도 `unknown`입니다.
- 점검 기록은 이력으로만 남고 교환 기준을 갱신하지 않습니다. `replacement` 기록만 일정을 계산합니다.
- 브레이크와 볼 조인트는 앞 왼쪽·앞 오른쪽·뒤 왼쪽·뒤 오른쪽 안내를 각각 반환합니다. 한 위치의 기록은 다른 위치 이력이나 일정을 갱신하지 않습니다. 위치가 불명확한 기존 기록은 해당 위치 이력으로 간주하지 않고 `record.component_position` 확인 대상으로 표시합니다.
- 로워암 교환은 `lower-arm`으로 별도 저장합니다. 볼 조인트의 정비 이력·관리 상태에는 반영되지 않으며, 로워암 자체의 제조사 점검·교환 기준은 확인되지 않아 다음 주기를 계산하지 않습니다. 과거 통합 항목 `lower-arm-ball-joint`는 마이그레이션으로 보존하고 새 입력에서는 숨깁니다.
- 작업 종류는 `action`과 질문 문구에 반영합니다. 점검 항목에 교환을 요구하지 않으며, `condition_based` 기준은 고정 교환주기나 다음 점검 날짜를 계산하지 않습니다.
- 규칙의 `first_interval_km`은 이전 같은 종류 작업 이력이 없는 경우 첫 기준을 제공합니다. 반복 점검은 해당 위치의 점검 기록만 다음 기준 계산에 사용합니다.
- 날짜가 없는 교환을 `created_at`으로 정렬하거나 정비일로 간주하지 않습니다. 여러 교환의 순서를 정할 수 없거나 날짜·주행거리가 충돌하면 계산을 보류합니다.
- 현재 주행거리는 `reference_date == as_of_date`일 때만 거리 기준에 사용합니다. 오래된 측정, 누락값, 주행거리 역전은 해당 축을 미확인으로 둡니다.
- 차량 `id`가 없거나 양의 정수가 아니면 기록을 안전하게 연결할 수 없으므로 계산을 보류하고 `vehicle.id`를 누락 필드로 반환합니다.
- 월 계산은 달력 기준이며 대상 월 말일에 맞춰 일자를 조정합니다. 경계값은 도달로 봅니다.
- 실제 주기나 교환 필요를 단정하지 않습니다. fixture 결과에는 `is_fixture=True`가 유지됩니다.

## 현재 구현의 적용 제외

실제 출처 후보를 프로토타입 계산에 사용합니다. 재사용 권한은 아직 확인되지 않았고, 계산 결과에 권리 상태를 표시합니다. 차량 고장 진단, 자료 이용 권한 판단, 증빙 자동 검증은 범위에 포함하지 않습니다.

## 경정비 확장 요구사항 및 현재 상태

2026-10-14 사용자 요청에 따라 소모품과 경정비를 함께 안내하는 기능을 추가 개발 범위로 확정합니다. 지원 사양은 국내 2021년형 K5 DL3 2.0 가솔린 스마트스트림 G2.0 CVVL 자동변속기 하나입니다. 다른 차량의 실제 교환 경험을 이 사양의 권장 주기로 전환하지 않습니다.

### 입력과 결과에 필요한 내용

- 주기 종류를 정기 교환 / 정기 점검 / 상태에 따른 정비로 구분합니다. 최초 기준과 반복 기준, 거리만 있는 기준도 처리해야 합니다.
- 차량의 현재 주행거리와 측정일, 운행조건을 사용합니다. 구동벨트 최초 72개월 계산 입력은 차량등록증의 최초 등록일로 받습니다. 이 날짜가 제조사의 인도일과 다를 수 있는 한계가 있으므로 해당 날짜를 근거로 표시하고, 모르면 시간축을 보류합니다. 모델 연식이나 중고차 구매일을 대신 대입하지 않습니다.
- 정비 기록은 항목, 점검·교환 구분, 작업일, 주행거리, 출처를 받습니다. 하체 부품은 정확한 부품명과 좌우·앞뒤 위치, 정비소 점검 결과, 권고 작업의 완료 여부를 추가로 표현해야 합니다.
- 부품명이나 위치가 모호하면 확인 전 상태로 남깁니다. 일상 표현에서 부품·위치를 추출할 때 사용자의 확인을 거치며 자동으로 확정하지 않습니다.
- 기록 없음은 미교환을 의미하지 않습니다. 제조사 일정은 참고 기준으로 제시할 수 있지만, 개인별 다음 교환 시점과 정상 상태는 확인된 이력·조건 범위에서만 안내합니다.
- 점검 기록은 점검 일정에, 교환 기록은 교환 일정에 반영합니다. 점검 한 번으로 해당 항목의 모든 교환·점검 기준을 초기화하지 않습니다.
- 결과에는 지금 확인할 항목, 확인된 관리 이력, 이력 미확인, 향후 관리 예정과 함께 판단 이유·출처·정비소 질문을 제공합니다.

### 구현 완료를 판단할 검증 사례

1. 통상조건의 90,000 km 차량을 등록해도 점화플러그를 100,000 km에 교환하라고 안내하지 않는다. 165,000 km 정기 기준과 이력 확인 상태를 구분해 표시한다.
2. 최초 구동벨트 점검 이력이 없는 90,000 km 차량은 최초 점검 기준 도달과 이력 확인 필요를 안내한다. 벨트 교환 필요나 고장으로 확정하지 않는다.
3. 점화플러그 교환 기록이 추가되면 해당 항목의 확인된 이력이 갱신된다. 다음 일정은 적용 조건과 기록의 날짜·주행거리 일관성을 확인해 계산한다.
4. 하체 부품 교환 기록은 해당 부품·위치에만 반영한다. 반대편 부품이나 하체 전체를 정비 완료로 표시하지 않는다.
5. 점검만 받은 기록과 부품을 교환한 기록이 서로 다른 결과를 만든다. 누락된 이력이나 모호한 부품·위치는 확인할 질문으로 연결한다.
6. 2018년형 JF 등 지원 밖 사양에는 DL3의 기준을 적용하지 않는다. 시연용 가상 이력은 실제 차량의 정비 증빙과 구분한다.
7. 통상조건 90,000 km 차량은 냉각수의 최초 200,000 km 기준과 실제 최초 등록일 기준 10년을 각각 계산한다. 등록일이 없으면 해당 시간축만 미확인으로 표시한다.
8. 냉각수 교환 기록은 해당 날짜와 주행거리부터 24개월·40,000 km 반복 기준을 다시 계산한다. 가혹조건에서는 별도 수치 기준을 임의로 적용하지 않는다.
