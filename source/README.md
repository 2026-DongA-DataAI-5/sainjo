# 차근 개발 초안

이 폴더는 수업 자료와 분리한 Flask 웹서비스 기본 구조입니다.
현재 가능한 것은 화면 이동, 가상 데이터 조회, 관리정보 필터, 차량 정보와 사용자가 입력한 이전 이력·정비 결과·정비소 질문 체크의 현재 브라우저 저장·재표시, 사용자 입력 데이터 JSON 내보내기입니다.
회원 인증·서버 DB 저장·제조사 기준 계산·OCR·외부 API는 아직 구현하지 않았습니다.

## 바로 실행하기

PowerShell에서 이 폴더를 연 다음 실행합니다.

```powershell
.\.venv\Scripts\python.exe app.py
```

브라우저에서 http://127.0.0.1:8081 를 엽니다. 종료는 실행 터미널에서 Ctrl+C입니다.
VS Code에서는 `Ctrl+Shift+B`를 눌러 기본 점검을 실행하고, `Ctrl+Shift+P` → `작업 실행` → `차근 개발 서버 실행`으로 서버를 켤 수 있습니다. 실행할 때는 이 프로젝트의 `.venv` Python을 사용합니다. 중단은 실행 터미널에서 `Ctrl+C`입니다. 디버깅은 `F5`를 누릅니다.
수업용 Python을 바꾸지 않고 이 폴더의 `.venv`만 사용합니다.

다른 PC에서 환경을 새로 만들 때:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe app.py
```

Activate.ps1을 실행하지 않아도 됩니다. Windows 실행 정책을 바꿀 필요가 없습니다.

## 코드 지도

```text
app.py                   서버 실행 진입점
chageun/
  __init__.py            Flask 앱 생성·기본 보안 헤더
  routes.py              화면 주소와 읽기 전용 API
  sample_data.py         가상 차량·관리항목·이력
  templates/             HTML 화면과 공통 틀
  static/css/app.css     화면 스타일·반응형 규칙
  static/css/webapp.css  모바일 하단 메뉴·터치 입력·반응형 앱 틀
  static/js/navigation.js 전체 메뉴의 키보드·화면 전환 보조
  static/js/app.js       관리항목 필터·현재 브라우저의 차량 정보 저장·표시
  services/              관리 판단·계산을 구현할 자리
  repositories/          MySQL 저장을 구현할 자리
.vscode/                 이 프로젝트만의 Python·실행 설정
requirements.txt         직접 의존성 Flask
requirements-lock.txt    이번 설치의 전체 패키지 버전
```

`routes.py`는 어느 화면을 보여 줄지, `services/`는 계산을, `repositories/`는 저장을 맡도록 나눴습니다.
차량 정보 입력→현재 브라우저 저장→대시보드 표시와 이전 이력·정비 결과 입력→현재 브라우저 저장→타임라인 표시 흐름을 구현했습니다. 저장 책임은 브라우저의 localStorage에 한정하며, 로그인·다른 기기 간 동기화·서버 DB는 구현하지 않았습니다. 관리항목과 일정은 저장 차량이나 입력 기록에 맞춰 계산하지 않고 계속 가상 예시로 표시합니다.

## 화면에서 꼭 지키는 원칙

- 이력 확인 여부와 현재 확인 시점을 분리합니다. 한 항목에 복수 표시가 가능합니다.
- 기록 없음은 미정비·미교환·교환필수로 변환하지 않습니다.
- JF와 DL3는 다른 세대입니다. 지원되지 않는 사양에 기준을 대입하지 않습니다.
- 가상 오일·필터 일정은 착수 명세서의 예시를 옮긴 값입니다. 서버에서 계산한 결과가 아닙니다.
- 제조사 관리기준 검토일은 2026.10.04, 화면의 가상 이력 확인일은 2026.10.06입니다.
- 이전 이력·정비 결과는 출처와 자료 확인일을 포함해 현재 브라우저의 localStorage에 저장하며, 대시보드 요약과 타임라인에서 확인하고 타임라인에서 개별 삭제할 수 있습니다. 브라우저를 바꾸거나 저장 데이터를 지우면 기록을 볼 수 없습니다.
- 정비소 질문 체크도 현재 브라우저에 저장해 방문 준비를 이어갈 수 있습니다. 체크는 정비 완료나 차량 상태 확인을 뜻하지 않습니다.
- 타임라인의 JSON 내보내기는 차량정보·저장한 관리 기록·질문 체크를 파일로 내려받습니다. 외부로 업로드하지 않습니다.
- 관리기록의 출처는 입력자가 선택한 값이며 자동으로 문서와 대조되지 않습니다. 화면 예시와 사용자가 입력한 기록을 구분해서 표시합니다.
- 입력한 차량·정비 정보를 현재 브라우저에 저장하므로 공용 기기에서는 사용 후 삭제하세요. 서버로 전송되지는 않지만 로그인·계정별 분리·서버 DB는 없습니다.

## 다음 개발 순서와 완료 조건

1. 팀이 첫 관리항목·사양·제조사 근거·운행조건을 확정한다.
2. 회원 인증과 MySQL 소유 관계를 연결한다. 다른 계정의 차량 조회·수정 요청이 차단돼야 한다.
3. 차량·이력을 서버 DB에 저장한다. 새로고침·재로그인 후 값이 유지돼야 하고, 입력한 계정 외에는 조회할 수 없어야 한다. 현재는 브라우저 저장만 동작한다.
4. 한 항목의 실제 계산을 연결한다. 미확인값으로 계산하지 않고 점검이 교환주기를 초기화하지 않아야 한다.
5. 현재는 이전 이력·정비 결과 입력과 브라우저 타임라인을 연결했다. 다음에는 이를 계정별 서버 DB로 옮기고 저장 실패·재조회 결과를 검증한다.
6. 확정 항목으로 확장하고 배포를 검증한다. 선택 OCR은 이 뒤에 검토한다.

교육 텍스트 마이닝 챌린지 인정 여부, 10종 선정, DB 운영·배포 조건은 팀 결정이 필요합니다.
지금은 MySQL 서버 설치·클라우드 연결·배포를 하지 않습니다. 실제 저장 구조를 확정한 뒤 필요한 패키지를 추가합니다.

## 첫 화면 구성

첫 방문에는 차근이 돕는 관리 흐름을 소개하고, 상단과 히어로·하단의 `차량 관리 시작하기` 버튼을 통해 `/start`로 이동합니다. `/vehicle`에서 입력한 정보는 현재 브라우저에 저장되고 `/dashboard`에서 다시 표시됩니다. 관리항목은 여전히 가상 예시입니다. 소개 화면은 `static/css/landing.css`를 사용하며, 900px·700px·380px 너비 구간에 맞춰 배치와 글자 크기를 조정합니다. 공통 앱 화면도 같은 파란색 계열을 사용합니다.

마이클 소개 페이지의 파란색 전체 폭 히어로, 상단 내비게이션, 모바일 화면 미리보기, 서비스 설명 구간과 반복 CTA를 UI 참고점으로 반영했습니다. 차근의 문구와 가상 차량 카드로 구성했으며, 예약·AI 진단·정비소 연계 기능은 소개에 넣지 않았습니다.

## 검토할 화면 방향

대시보드에서는 저장 차량 정보와 가상 관리항목을 분명히 분리합니다. 직접 입력한 이전 이력·정비 결과는 타임라인에서 화면 예시와 따로 표시합니다. 입력 출처는 자동 검증되지 않으며 관리 주기도 차량 이력에 맞춰 계산하지 않습니다.

## 구현한 첫 개발 단위

- 차량의 제조사·모델·세대·연식·사양·주행거리·기준일을 입력하고 저장합니다.
- 값은 현재 브라우저의 localStorage에만 저장되며, 새로고침 후에도 차량 화면과 대시보드에 다시 표시됩니다.
- 모르는 값은 비워 둘 수 있고 대시보드에서는 `미확인`으로 표시합니다. 입력한 K5 JF/DL3 값으로 제조사 기준을 연결하거나 계산하지 않습니다.
- 차량 정보 삭제는 차량 화면에서 확인 후 실행할 수 있습니다.
- 대시보드의 관리정보·이력·일정은 가상 데이터이며 입력 차량에 맞춘 결과가 아닙니다.

## 구현한 두 번째 개발 단위

- 이전 이력·정비 결과를 입력해 브라우저 localStorage에 저장하고 `/timeline`에서 다시 표시합니다.
- 점검과 교환을 구분하고, 날짜·주행거리를 모르면 미확인으로 둡니다. 점검을 교환으로 바꾸거나 관리주기를 계산하지 않습니다.
- 입력한 메모는 HTML로 실행하지 않고 글자로만 표시합니다. 각 기록은 확인창을 거쳐 현재 브라우저에서 삭제할 수 있습니다.
- 저장 기록은 입력자가 선택한 출처·자료 확인일·저장일을 표시하며, 외부 문서와 자동 대조하지 않습니다.
- 대시보드에는 최근 사용자 입력 기록을 최대 3건 보여 주고 전체 목록은 타임라인에 둡니다. 저장된 이력으로 관리 시점을 계산하지 않습니다.
- 정비소 질문 체크 상태는 브라우저를 닫았다 다시 열어도 유지됩니다. JSON 내보내기로 사용자 입력 정보를 파일로 저장할 수 있습니다.

## 이번 작업에서 확인한 결과

- 화면·샘플 API·정적 파일 14개 요청이 정상 응답했습니다.
- 없는 관리항목은 404, 미구현 저장 요청은 405로 처리됩니다.
- 브라우저에서 이력 미확인 필터, JF 안내, 날짜 미확인 타임라인을 확인했습니다.
- 대시보드 320·768·1024·1440px 폭에서 페이지 전체 가로 넘침이 없었습니다.
- 패키지 의존성 검사를 통과했고 전역 Python에는 Flask를 설치하지 않았습니다.
- 기록 입력→타임라인 표시→기록 삭제 흐름을 브라우저에서 확인했습니다. 이 테스트용 입력은 삭제했습니다.
- 정비소 질문 체크가 새로고침 뒤에도 복원되는 것과 대시보드 기록 요약을 브라우저에서 확인했습니다. 시험용 체크·기록은 정리했습니다.
- JSON 내보내기로 실제 파일을 내려받고 저장한 차량·정비 기록이 포함되는 것을 검수 브라우저에서 확인했습니다.
- 실제 회원 인증·DB 지속 저장·주기 계산·사용성 검증 통과를 뜻하지 않습니다.

개발 미리보기 서버가 이미 실행 중이면 VS Code 작업을 다시 실행하기 전에 기존 서버를 종료해야 합니다.
별도 VS Code 실행용 프로필은 이 대화 작업폴더의 work/차근_vscode_profile에만 생성했습니다.

## 반응형 웹앱 보정 · 2026.10.07

- 768px 이하 화면은 상단의 차근 로고·전체 메뉴와 하단의 홈·차량·기록·질문·타임라인 메뉴를 사용합니다. 이전 이력 입력과 서비스 소개는 전체 메뉴에서 접근할 수 있습니다.
- 넓은 화면은 기존 왼쪽 메뉴와 두 열 입력폼을 사용합니다. 좁은 화면에서는 입력폼·관리 카드를 한 열로 배치합니다.
- 모바일 글자와 버튼을 키웠으며 입력칸은 16px 이상, 주요 터치 영역은 44px 이상입니다. 화면 가장자리의 안전 여백을 반영하고 페이지 하단 내용까지 스크롤할 수 있게 했습니다.
- 전체 메뉴는 Enter로 열고 Escape로 닫을 수 있습니다. 메뉴 바깥을 누르거나 PC 화면 폭으로 바꾸면 닫힙니다. JavaScript 없이도 HTML 기본 메뉴는 사용할 수 있습니다.
- 브라우저 저장 키와 입력 데이터 형식은 변경하지 않았습니다. 기존 브라우저의 차량·정비 기록·질문 체크는 계속 사용합니다.
- 검수용 Chrome에서 320·390·768·1024·1440px의 10개 화면(404 화면 포함), 총 50개 조합을 확인했습니다. 가로 넘침이 없었고 차량·기록 저장과 새로고침, 기록 삭제, 질문 체크 복원, JSON 다운로드, 키보드 메뉴 조작을 확인했습니다. 실제 휴대폰의 키보드·Safari 검수는 별도로 필요합니다.

서버 실행 방법은 동일합니다. 이미 실행 중인 서버는 종료 후 다시 실행하고 브라우저에서 `Ctrl+F5`로 새 화면을 불러오세요. 이번 보정은 반응형 화면과 내비게이션에 해당하며 설치형 PWA·오프라인 저장소·계정 동기화를 추가한 것은 아닙니다.
